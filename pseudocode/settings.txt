# =============================================================================
# AFFICHAGE
# =============================================================================
#
# La fenêtre fait 1024×768 pixels.
# On a choisi cette résolution parce que :
#   - C'est un ratio 4:3 comme la GBA, ça colle avec notre style top-down rétro
#   - C'est divisible par 32 (notre taille de tile) → 1024/32 = 32, 768/32 = 24
#     Donc pas de pixel coupé en bord d'écran, tout tombe juste
#   - C'est assez grand pour être confortable sur un écran moderne
#
# Les tiles font 32×32 pixels.
# On a hésité entre 16, 32 et 64. On est parti sur 32 parce que :
#   - C'est le standard dans les tutos Pygame (Clear Code, KidsCanCode...)
#   - La plupart des tilesets gratuits sont en 32×32
#   - 16 c'était trop petit (illisible), 64 trop gros (trop peu de tiles visibles)
#   - Avec 1024×768 ça nous donne 32×24 tiles visibles, c'est largement suffisant
#
# FPS à 60, c'est le standard Pygame, pas de raison de faire autrement.

LARGEUR_ECRAN ← 1024
HAUTEUR_ECRAN ← 768
TAILLE_TILE ← 32
FPS ← 60
TITRE_FENETRE ← "Pokémon La Plateforme"


# =============================================================================
# GRILLE CALCULÉE
# =============================================================================
#
# Ça c'est juste des valeurs qu'on déduit des constantes au-dessus.
# On les pose ici pour pas avoir à recalculer à chaque fois dans le code.
# camera.py en a besoin pour savoir combien de tiles dessiner,
# map_manager.py aussi pour optimiser le rendu.

TILES_EN_LARGEUR ← LARGEUR_ECRAN / TAILLE_TILE      # = 32
TILES_EN_HAUTEUR ← HAUTEUR_ECRAN / TAILLE_TILE       # = 24

# → Utilisé par pokemon.py et combat_ui.py

}


# =============================================================================
# COMBAT
# =============================================================================
#
# Chance de louper : 5%.
# Avant chaque attaque, on tire un nombre entre 0 et 1.
# Si c'est en dessous de 0.05 → l'attaque rate, message "L'attaque a échoué !"
# On a pris 5% parce que dans les vrais Pokémon la plupart des attaques
# ont 95-100% de précision. 10% ou 15% c'était trop frustrant pour le joueur.
# → Utilisé par damage_calculator.py
#
# Dégâts minimum : 1.
# Même si un Pokémon a une défense de ouf, il prend toujours au moins 1 dégât.
# Sans ça, un tank serait littéralement invincible et le combat serait bloqué.
# C'est aussi dans notre doc technique : "Le minimum de dégâts est 1".
# → Utilisé par damage_calculator.py
#
# Ordre de combat : aléatoire à chaque tour.
# On n'a pas de stat vitesse dans notre modèle de Pokémon (on a juste
# PV, attaque, défense), donc on tire au sort qui joue en premier.
# Ça rajoute un peu d'incertitude, c'est pas mal tactiquement.
# → Utilisé par combat.py

CHANCE_MISS ← 0.05
DEGATS_MINIMUM ← 1
ORDRE_COMBAT ← "aleatoire"

# =============================================================================
# CYCLE JOUR / NUIT
# =============================================================================
#
# Le jeu a un cycle jour/nuit accéléré : 24h en jeu = 1h en vrai.
#
# Le temps est stocké en minutes de jeu, de 0 à 1439 :
#   0    = minuit
#   360  = 6h00 (début du jour)
#   720  = midi
#   1200 = 20h00 (début de la nuit)
#   1439 = 23h59, après ça repart à 0
#
# Le RATIO_TEMPS c'est le truc clé : chaque seconde réelle = 0.4 minute de jeu.
# Dans le code, à chaque frame on fait :
#   temps_jeu += delta_time_en_secondes × RATIO_TEMPS
# → Utilisé par day_night_cycle.py
#
# La pénalité jour/nuit : -20% sur l'attaque ou la défense.
# Si un Pokémon diurne se bat de nuit (ou nocturne de jour), une de ses stats
# est multipliée par 0.80. Ça force le joueur à adapter son équipe.
# On a choisi 20% parce que 10% c'était pas assez visible et 30% trop punitif.
# → Utilisé par damage_calculator.py

DEBUT_JOUR ← 360
DEBUT_NUIT ← 1200
DUREE_CYCLE_JEU ← 1440
DUREE_CYCLE_REEL ← 3600
RATIO_TEMPS ← DUREE_CYCLE_JEU / DUREE_CYCLE_REEL
PENALITE_JOUR_NUIT ← 0.20


# =============================================================================
# ÉCONOMIE
# =============================================================================
#
# On a une seule monnaie dans le jeu : les crédits.
# Ils servent à acheter des objets en boutique ET à payer l'entrée du tournoi.
# Du coup le joueur doit faire des choix : est-ce qu'il claque tout en potions
# ou il économise pour le tournoi ? C'est cette tension qui rend le truc
# stratégique.
#
# Ce qu'on gagne par victoire :
#   - B1 (dresseur débutant) : 20 crédits
#   - B2 (intermédiaire) : 30 crédits
#   - B3 (expert, tournoi) : 50 crédits
# → Utilisé par credits_manager.py
#
# Pour le coût du tournoi on a fait le calcul :
#   Zone 1 : ~3 B1 (60) + ~2 B2 (60) = 120 crédits
#   Zone 2 : ~2 B1 (40) + ~3 B2 (90) = 130 crédits
#   Total dresseurs : ~250 crédits
#   + les défis si on les implémente (Could Have) : ~100-150 en bonus
# 150 crédits ça représente environ 60% des gains dresseurs.
# Le joueur peut acheter quelques objets et quand même accéder au tournoi
# sans forcément battre tout le monde.
# → Utilisé par tournament.py et credits_manager.py
#
# Le bracket fait 4 combats en élimination directe.
# Les Pokémon ne sont pas soignés entre les combats, donc c'est déjà bien
# costaud. On voulait que le tournoi soit un vrai défi de fin de jeu.
# → Utilisé par tournament.py

CREDITS_VICTOIRE_B1 ← 20
CREDITS_VICTOIRE_B2 ← 30
CREDITS_VICTOIRE_B3 ← 50
COUT_ENTREE_TOURNOI ← 150
BRACKET_TAILLE ← 4
